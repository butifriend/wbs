# WBS 일정 관리

시작일과 M/D(공수)를 입력하면 대한민국 공휴일·주말을 제외한 **영업일 기준**으로 종료일이 자동 계산되는 단일 HTML 파일 기반 WBS(작업분류체계) 관리 도구입니다.

**바로 열기 →** https://butifriend.github.io/wbs/wbs.html

---

## 담당자 (조회)

**관리자에게 받은 링크를 한 번 클릭하면 끝입니다.** 연결이 자동으로 잡히고, 이후에는 북마크로 열면 됩니다. 주소를 입력하거나 관리할 일은 없습니다.

조회 전용 모드에서는 이렇게 동작합니다.

| 할 수 있는 것 | 할 수 없는 것 |
|---|---|
| 조회, 부서 전환, 조회기간 필터 | 내용 편집 |
| WBS / 간트차트 / 타임라인 탭 | 그룹·업무 추가, 삭제 |
| 펼치기·접기 | 그룹·업무 순서 변경 |
| 엑셀·CSV·JSON·HTML 내보내기, 인쇄 | 부서 관리 |

우측 상단에 **조회 전용** 배지가 표시됩니다.

## 관리자 (편집)

기능모음 → **관리자 모드** 에서 열쇠를 입력하면 편집이 열립니다. 열쇠는 그 브라우저에 기억되므로 한 번만 입력하면 됩니다. 배지가 **관리자** 로 바뀝니다.

해제하려면 기능모음 → **조회 전용으로 전환**.

---

## 화면 구성

**탭 3개**

- **WBS** — 표 형태. 그룹 아래 상세업무를 두고 시작일·M/D를 입력하면 종료일이 자동 계산됩니다.
- **간트차트** — 주 단위 격자. 구분별 색으로 표시됩니다.
- **타임라인** — 그룹을 가로 레인으로 둔 로드맵. 분기 / 월 / 주 3단 축이며, M/D 0인 업무는 마일스톤(★)으로 표시됩니다.

**조회기간** — 달력 아이콘을 눌러 연도 + 전체/올해/전년도/상반기/하반기/분기/월로 걸러 봅니다. 표·요약·간트·타임라인에 함께 적용됩니다.

**펼치기 · 접기** — 전체 또는 완료 그룹만 일괄로 접고 펼칩니다. 완료된 그룹은 기본으로 접혀서 맨 아래에 놓입니다.

> 접기 상태와 조회기간은 **각자 브라우저에만** 저장됩니다. 팀원 화면에 영향을 주지 않습니다.

## 처음 설정하기 (관리자만)

### 1. 구글 시트 + Apps Script

1. 구글 시트를 새로 만듭니다.
2. **확장 프로그램 → Apps Script** 를 엽니다.
3. 기본 코드를 지우고 [`google-apps-script/Code.gs`](./google-apps-script/Code.gs) 내용을 전부 붙여넣습니다.
4. **배포 → 새 배포** → 좌측 **⚙ 유형 선택 → 웹 앱**
   - 실행 계정: **나**
   - 액세스 권한이 있는 사용자: **전체**
5. 배포 후 나오는 URL(`.../exec` 로 끝남)을 복사합니다.
6. `wbs.html` 을 열고 기능모음 → **동기화 설정** 에 붙여넣고 **연결 저장**.

> ⚙ 유형 선택을 누르지 않으면 "라이브러리"로 배포되어 `/macros/library/...` 주소가 나옵니다. 그건 데이터 주소가 아닙니다. **`/exec` 로 끝나는지 꼭 확인하세요.**

### 2. 관리자 열쇠

Apps Script 편집기 좌측 **⚙ 프로젝트 설정 → 스크립트 속성 → 속성 추가**

```
속성:  ADMIN_KEY
값:    (원하는 문자열)
```

이 값을 넣으면 **쓰기에 열쇠가 필요**해집니다. 읽기는 그대로 열려 있어 담당자가 조회할 수 있습니다.

- 열쇠는 코드가 아니라 스크립트 속성에 들어가므로 **저장소에 올라가지 않습니다.**
- 유출되면 이 값만 바꾸면 됩니다. **재배포 불필요.**
- 설정하지 않으면 누구나 저장할 수 있습니다(잠금 없음).

### 3. 담당자에게 링크 배포

기능모음 → **담당자용 링크 복사** → 사내 메신저·메일로 전달.

받은 사람이 한 번 열면 연결이 자동 설정되고, 주소창의 파라미터는 즉시 지워집니다.

> 링크에는 **관리자 열쇠가 담기지 않습니다.** 링크를 받은 사람은 조회 전용입니다.
> 링크는 사내 채널로만 공유하세요. 저장소·README에는 넣지 마세요.

> Code.gs에는 리비전만 돌려주는 가벼운 응답(`?action=rev`)이 있습니다. 주기 확인에 쓰여 서버 부담을 크게 줄입니다. 구버전이 배포돼 있어도 동작은 하지만, **재배포하는 편이 낫습니다.**

### 4. 코드를 갱신할 때

Apps Script 편집기에서 코드를 교체한 뒤 **배포 → 배포 관리 → 연필 아이콘 → 버전: 새 버전 → 배포**.
이렇게 하면 **URL이 유지**되어 팀원이 주소를 다시 등록할 필요가 없습니다.

## 부서 나누기

부서마다 데이터를 완전히 분리해서 관리할 수 있습니다.

- 기능모음 → **부서 추가 / 부서 이름 변경 / 부서 목록에서 제거** (관리자만)
- 툴바 좌측 드롭다운으로 전환
- 부서마다 **리비전이 따로**라 충돌 감지도 독립적으로 동작합니다

시트 구성은 이렇습니다.

| 시트 | 내용 |
|---|---|
| `_Depts` | 부서 목록 (숨김) |
| `Data` | "기본" 부서 |
| `Data_<id>` | 그 외 부서 |

> **부서를 제거해도 데이터 시트는 남습니다.** 목록에서만 빠지므로 실수로 눌러도 되살릴 수 있습니다. 완전히 지우려면 구글 시트에서 해당 탭을 직접 삭제하세요.

## 동작 방식

- 데이터 입력은 wbs.html 화면에서만 합니다. 구글 시트를 직접 열어 편집할 필요가 없습니다.
- **저장 버튼이 없습니다.** 고치면 약 1.5초 뒤 저장됩니다. 툴바 배지가 `☁ 동기화됨` 으로 바뀌면 올라간 것입니다.
- 20초마다 서버를 확인해 다른 사람의 변경을 받아옵니다. 탭을 다시 보는 순간에도 한 번 확인합니다.
- 다른 탭에 있는 동안에는 확인하지 않습니다. Apps Script의 하루 실행 시간을 아끼기 위해서입니다.

### 동시에 편집하면

**합칩니다.** 어느 쪽을 버릴지 묻지 않습니다.

마지막으로 서버와 같았던 내용을 기준으로, 내 화면과 서버를 **칸 단위로** 비교합니다. 기준과 다른 쪽이 누군가 고친 것이므로, 서로 다른 곳을 고쳤다면 양쪽이 모두 남습니다.

| 상황 | 결과 |
|---|---|
| 서로 다른 행을 고침 | 둘 다 남음 |
| 같은 행의 다른 칸을 고침 | 둘 다 남음 |
| **같은 칸**을 고침 | 나중에 저장한 쪽이 남고, 배지에 `같은 칸 1곳은 내 입력 유지` 로 알려 줌 |
| 양쪽이 각자 행·그룹을 추가 | 둘 다 남음 |
| 내가 지운 행 | 지운 상태 유지 |
| 상대가 지운 행 | 내가 손대지 않았으면 삭제를 따르고, 고쳤으면 살림 |
| 순서 변경 | 내가 순서를 바꿨으면 내 순서, 아니면 서버 순서 |

합칠 때 배지에 `다른 사람 변경 합침 (수정 2)` 처럼 무엇이 들어왔는지 표시됩니다.

> 입력 중에는 화면을 다시 그리지 않습니다. 치던 글자와 커서가 날아가기 때문입니다. 데이터는 이미 합쳐져 있고, 칸을 벗어나면 화면에 반영됩니다.

### 연결이 끊겼을 때

이 브라우저의 로컬 데이터로 보여주고 **자동 업로드를 중지**합니다. 서버를 못 읽은 상태에서 오래된 로컬 데이터가 팀 시트를 덮어쓰는 사고를 막기 위한 장치입니다. 툴바에 `⚠ 업로드 중지됨` 이 표시됩니다.

- 첫 연결이 실패하면 2초 뒤 **한 번 더 시도**합니다. 한동안 쓰지 않은 Apps Script는 첫 요청이 느려 실패하는 일이 있습니다.
- 저장에 실패하면 5초 → 10초 → … 최대 1분 간격으로 **스스로 다시 시도**합니다.
- 연결이 돌아오면 주기 확인이 막힌 상태를 풀고 밀린 내용을 합쳐 올립니다.
- 당장 시도하려면 `⚠ 업로드 중지됨` 배지를 클릭하세요.

기준이 없는 경우(이 브라우저가 서버를 **한 번도** 읽지 못한 채 편집한 경우)에만 어느 쪽을 남길지 물어봅니다. 합칠 기준이 없어 무엇이 내 변경인지 판단할 수 없기 때문입니다.

## 보안

| 항목 | 상태 |
|---|---|
| 데이터 **쓰기** | 관리자 열쇠 필요 |
| 데이터 **읽기** | URL을 아는 사람은 누구나 (로그인 불필요) |

즉 URL이 새면 **조회는 가능하지만 수정·삭제는 불가능**합니다.

알아두실 한계입니다.

- 관리자 PC를 쓸 수 있는 사람은 브라우저 저장소에서 열쇠를 꺼낼 수 있습니다.
- 조회까지 막으려면 구글 계정 기반 인증이 필요한데, 지금처럼 GitHub Pages에서 화면을 서빙하는 구조로는 CORS 때문에 불가능합니다. 화면을 Apps Script(HtmlService)로 옮겨야 합니다.

**동기화 URL을 저장소에 넣지 마세요.** README·커밋 메시지·이슈 어디에도요. 한번 올리면 git 히스토리에 남아 지워도 꺼낼 수 있습니다.

## 동기화 없이 쓰기

연결을 등록하지 않으면 데이터가 그 브라우저의 로컬 저장소에만 저장됩니다. `wbs.html` 을 더블클릭해 바로 쓸 수 있고, 같은 브라우저로 다시 열면 이어서 작업할 수 있습니다. 권한 잠금도 없습니다.

혼자 쓰거나 시험해볼 때 적합합니다.

## 참고

- **공휴일** — 양력 공휴일과 대체공휴일은 연도에 관계없이 자동 계산됩니다(제헌절 2026년 재지정 반영). 설날·추석·부처님오신날처럼 음력 기준인 공휴일은 계산식으로 구할 수 없어 **2027년까지** 등록돼 있습니다. 그 이후 일정이 있으면 화면에 경고가 뜨며, 공휴일 관리에서 직접 추가할 수 있습니다.
- **직접 추가한 공휴일**은 브라우저별 로컬 저장소에만 남습니다. 팀 전체가 같은 목록을 쓰려면 각자 추가해야 합니다.
- **내보내기(JSON·CSV·엑셀·HTML)는 조회기간과 무관하게 전체를 내보냅니다.** JSON 내보내기가 백업 수단이라 일부만 나가면 위험하기 때문입니다.
- **M/D 0** 은 공수 없는 마일스톤으로 보고 종료일을 시작일과 같게 둡니다. 타임라인에서는 ★ 로 표시됩니다.

## 부록: JSON 파일로 주고받기 (구버전 방식)

구글 시트 연결 이전에 쓰던 방법입니다. 지금은 필요 없지만, 백업을 남기거나 연결 없이 데이터를 전달할 때 쓸 수 있습니다.

1. 기능모음 → **JSON 내보내기** 로 `wbs_YYYY-MM-DD.json` 을 받습니다.
2. 파일을 전달합니다. (저장소에 두려면 [`JSON 백업/wbs-data.json`](./JSON%20백업/wbs-data.json) 에 덮어쓰고 커밋)
3. 받는 쪽은 기능모음 → **JSON 가져오기** 로 불러옵니다.

> 가져오기는 화면의 데이터를 **통째로 교체**합니다. 구글 시트에 연결된 상태라면 그 내용이 시트에도 반영되니 주의하세요.
