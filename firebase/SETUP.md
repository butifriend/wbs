# Firebase 설정 (관리자용)

구글 시트 대신 Firestore 에 데이터를 두기 위한 준비입니다. **한 번만 하면 됩니다.**

이 문서의 1~5단계를 마치고 **① 설정값**과 **② 문서 ID**를 알려주시면 화면 쪽을 연결하겠습니다.

---

## 왜 옮기나

| | 구글 시트 | Firestore |
|---|---|---|
| 한 덩어리 최대 | 50,000자 (≈ 업무 200건) | 1 MiB (≈ 업무 3,500건) |
| 호출 한 번 | **2~4초** (측정값, 고정) | 100~300ms |
| 남의 변경 | 20~40초마다 되물음 | **즉시 밀어 줌** |
| 무료 한도 | 스크립트 실행 시간 | 하루 읽기 5만 / 쓰기 2만 |

용량보다도 **속도**가 옮기는 이유입니다. Apps Script 는 응답 크기와 무관하게 호출당 2~4초가 고정으로 드는데, 그게 "동기화 중", "저장 중"이 길게 느껴지던 원인입니다.

---

## 1. 프로젝트 만들기

1. https://console.firebase.google.com 접속
2. **프로젝트 추가** → 이름 예: `wbs-schedule`
3. Google 애널리틱스는 **사용 안 함** (필요 없습니다)

## 2. Firestore 켜기

콘솔 좌측 메뉴에서 **Firestore** 를 엽니다.

- 새 콘솔: **Databases & Storage → Firestore**
- 예전 콘솔: **빌드(Build) → Firestore Database**

**데이터베이스 만들기 (Create database / Add database)** 를 누르고 아래대로 고릅니다.

| 물어보는 것 | 고를 것 | 이유 |
|---|---|---|
| 버전 (Edition) | **Standard edition** | Enterprise 는 MongoDB 호환용이고 요금 체계가 다릅니다 |
| 데이터베이스 ID | **`(default)`** 그대로 | 화면 코드가 기본 데이터베이스를 씁니다 |
| 위치 (Location) | **asia-northeast3 (Seoul)** | 가까울수록 빠릅니다. **나중에 못 바꿉니다** |
| 보안 규칙 시작 모드 | **프로덕션 모드 / 잠금(locked)** | 규칙은 4단계에서 넣습니다 |

> 테스트 모드로 만들면 **30일 동안 누구나 읽고 쓸 수 있습니다.** 반드시 프로덕션(잠금)으로 시작하세요. 잘못 골랐어도 4단계에서 규칙을 덮어쓰면 됩니다.

만들고 나면 빈 **데이터 / 규칙 / 색인** 탭이 보입니다. 여기까지가 2단계입니다.

## 3. 관리자 계정 만들기

편집하는 분만 로그인합니다. 조회만 하는 담당자는 로그인하지 않습니다.

**3-1. 로그인 방식 켜기**

1. 좌측 **Authentication** (예전 콘솔은 **빌드 → Authentication**) → **시작하기**
2. **Sign-in method** 탭 → 공급업체 목록에서 **이메일/비밀번호**
3. 맨 위 **사용 설정(Enable)** 토글만 켭니다 — 그 아래 "이메일 링크"는 끈 채로 둡니다
4. **저장**

**3-2. 계정 만들기**

1. **Users** 탭 → **사용자 추가**
2. 이메일: `admin@douzone.com`
3. 비밀번호: 원하는 값 (12자 이상 권장)
4. **사용자 추가**

> 이 주소는 **로그인 아이디로만 씁니다.** 실제 메일함이 아니어도 되고, Firebase 가 메일을 보내지도 않습니다.

> 비밀번호를 여럿이 나눠 쓰는 구조입니다. **누가 고쳤는지는 알 수 없고**, 새면 편집하는 분 전원에게 다시 알려야 합니다. 바꾸실 때는 Users 탭에서 해당 계정의 ⋮ → 비밀번호 재설정.

## 4. 보안 규칙 넣기

1. **Firestore → 규칙(Rules)** 탭
2. 편집기 안을 클릭하고 `Ctrl+A` → `Delete` 로 **전부 지웁니다**
3. [`firestore.rules`](./firestore.rules) 내용을 통째로 붙여넣습니다
4. 파일 아래쪽 관리자 계정이 `'admin@douzone.com'` 으로 돼 있는지 확인합니다 (3단계에서 만든 것과 같아야 합니다)
5. **게시(Publish)** 를 누릅니다

게시 직후 편집기 위에 오류가 없으면 성공입니다. 빨간 줄이 뜨면 대개 따옴표나 쉼표 문제입니다.

규칙이 하는 일입니다.

- **읽기** — 문서 ID 를 아는 사람이면 됩니다. 지금 "링크를 받은 사람만" 과 같은 수준입니다
- **목록 조회 차단** — 이게 열려 있으면 문서 ID 가 비밀이 되지 못합니다
- **쓰기** — `admin@douzone.com` 으로 로그인했을 때만. 비밀번호는 Firebase 가 보관하며 화면 코드에는 들어가지 않습니다

## 5. 웹 앱 등록하고 설정값 받기

1. 좌측 위 **⚙ 프로젝트 설정** → 하단 **내 앱** → **웹(</>)** 아이콘
2. 앱 닉네임: `wbs` → 등록 (Firebase Hosting 은 **체크하지 않습니다**)
3. 나오는 `firebaseConfig` 를 **통째로** 복사해 주세요

```js
const firebaseConfig = {
  apiKey: "...",
  authDomain: "....firebaseapp.com",
  projectId: "...",
  storageBucket: "...",
  messagingSenderId: "...",
  appId: "..."
};
```

> **이 설정값은 비밀이 아닙니다.** 저장소에 넣어도 됩니다. Firebase 는 설정값이 아니라 **보안 규칙**으로 막는 구조라, 공식 문서에서도 공개를 전제로 합니다. 지금까지 Apps Script 주소를 숨겨 온 것과는 다릅니다.

## 6. 도메인 허용

1. **Authentication → Settings → 승인된 도메인**
2. `butifriend.github.io` 가 없으면 **도메인 추가**

## 문서 ID

데이터는 `wbs` 컬렉션의 문서 하나에 담깁니다. **문서 ID 가 곧 열쇠**입니다 — 지금 `?s=` 링크가 하던 역할입니다.

**문서 ID 는 이 문서에 적지 않습니다.** 저장소가 공개라 적는 순간 열쇠가 아니게 됩니다. 관리자에게 따로 전달합니다.

직접 만드시려면 브라우저 주소창에 `about:blank` 를 열고 F12 콘솔에서 아래를 실행하세요.

```js
crypto.randomUUID().replace(/-/g, '')
```

> 이 ID 는 **저장소에 넣지 마세요.** 지금 Apps Script 주소를 다루던 것과 같습니다. 담당자에게는 `wbs.html?s=<문서ID>` 형태의 링크로 전달하게 됩니다.

---

## 알아두실 점

**조회에 로그인이 없다는 것은** 문서 ID 를 아는 사람은 누구나 읽는다는 뜻입니다. 지금과 같은 수준이고, 더 잠그려면 조회에도 로그인을 걸어야 합니다 (규칙에서 `allow get: if true;` 를 `allow get: if request.auth != null;` 로 바꾸면 됩니다).

**무료 한도**는 하루 읽기 5만 / 쓰기 2만입니다. 팀 규모로는 여유가 큽니다. 다만 편집할 때마다 쓰기가 한 번씩 들어가므로, 여러 명이 종일 고치는 날에는 저장 간격을 조금 늘리는 편이 안전합니다.

**구글 시트는 지웁니다 않습니다.** 옮긴 뒤에도 Apps Script 배포와 시트를 그대로 남겨 두어, 문제가 생기면 되돌릴 수 있게 합니다.
